# E32 实验报告｜设计与执行记录

2026-11-16（北京时间）在 zvanadium 的 E30 测试网络开始。正式问题是候选挂心是否提高「先承诺 → 自行预约 → 实际醒来 → 读取正式版 → 写下符合原目标的核对结果」的完成率。详细分组与复跑说明见 [实验设计](README_zh.md)。

## 从 E31 到 E32

E31 观察到有挂心组预约更多，但八条提醒都在十分钟窗口之外。E32 将观察上限预定为 24 小时，并在首条公告后 15 分钟静默更新 Cloud 草稿。它允许模型在原承诺下重新预约。正式分析跟踪提醒投递和语义一致性，避免把状态值或工具调用意图当成外部结果。

## 已验证的准备工作

- E30 Cloud 通过实际 HTTPS 健康检查。使用 Alice 发布并通过 Bob 只读账号独立验证草稿与正式版散列。
- 隔离模板首次生成因未写入 Profile 补丁失败，修复后六种组合均通过真实 DeepSeek Flash 自动反思生成一条候选挂心。每条候选引用对应组合的历史经历。参见 [冻结材料与持久化反思](.runtime/seed-retry/seeds.json)。
- 校准和正式批次使用独立 DSH_HOME。终止后清理临时共享、实验进程和复制的凭据。日志只保留脱敏后的工具轨迹与消息。

## 短窗技术验证

独立的无回访指示短窗冒烟在两组都观察到完整履约。安排在 90 秒后的正式版替换已经过 Bob 账号实际读取核验。随后，两组分别收到各自创建的提醒，下载相同正式版，写下版本 v3.4 和来源 ARC-718。按首轮承诺复核后，两组均符合条件。此批次用于检验基础设施与取证判定，单对结果不能用于估计挂心效应。

## 校准发现的 Cloud 隔离问题及修正

第一轮六对校准都自行设置提醒，之后实际收到提醒并成功读到本对正式版。六份正式版实际发布时间比公告晚约 4.9–6.7 秒，发布前后的散列均与冻结材料相符。审查持久记录时，发现一位居民还读到了另一对的共享目录。原因是首轮校准的 12 个会话共用 Cloud 测试账号，提示中的目录限定没有限制账号可见范围。

因此，随后刚启动的共享账号正式批次被停止并从正式分析排除。原始证据保存在 .runtime/formal-unscoped，对应临时进程、凭据和共享已清理。修正后，每对由 OCC 创建独立账号，并检查账号根目录只有本对的只读共享。再做两对短窗技术验证和六对完整校准。48 对正式批次仅在修正后的校准门槛通过后继续。两种账号方案的数据不合并。

## 隔离后的验证与执行状态

隔离后两对定时冒烟已全部完成。四个会话均收到实际提醒，在第二回合下载与各自正式版散列和正文标记一致的文件，留下可复核的持久记录。两对账号交叉尝试读取对方目录，均返回 HTTP 404。已确认两个冒烟账号已清理。这个阶段明确要求创建提醒，因此它只用于检验系统链路。

截至 17:21（北京时间），隔离后的六对行为校准已获取 12 个首轮检查点，仍在等待各对正式版发布及自主回访。正式批次由 VM 上独立的管线等待校准通过后启动。管线结束时自动保存配对摘要、逐对事件索引和去除组别标记的复核包。完整履约指标待全部会话结束且候选记录复核后填写。
