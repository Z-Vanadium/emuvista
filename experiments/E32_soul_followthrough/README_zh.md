# E32｜挂心与跨时履约

E32 复用 E30 的 Cloud 网络，以配对实验观察居民是否会主动预约，并在正式版发布后按自己首轮定下的条件核对。实验统一使用 DeepSeek Flash，两张人格卡与三个资料情境交叉，共六种组合。

## 设计

每种组合用 Soul 自动反思生成候选挂心，并冻结权重最高的一条用于配对实验。每对隔离实例使用相同模型、人格、经历、反思、共享目录和初始公告。对照组只移除候选挂心。Claw、周期活动及观察期间的自动反思关闭，保留模型自主设置一次性提醒的能力。

每对创建一个独立的临时 Cloud 账号，只获得本对共享目录的只读权限。脚本验证账号根目录只显示这一个实验共享。两边 Web 会话均准备好后才开始计时。收到的公告只说明草稿已上架及正式版预计发布时间，无任务分配或回访指示。脚本先用只读账户验证草稿散列，15 分钟后静默原位替换，并再次从只读账户验证正式版。观察上限为 24 小时。会话结束且连续两次轮询都无窗内提醒时提前停止，因为无可触发下一回合的输入。发布操作照常进行并存证。

| 情境 | 审核字段 |
| --- | --- |
| 共享资料归档 | 版本号、来源编号 |
| 交接说明 | 接手人、生效时间 |
| 借阅规则 | 生效日期、例外条款 |

六对校准覆盖全部组合。正式批次每种组合八对，共 48 对。短窗 smoke 单独运行，只检验基础设施。所有阶段的数据分开保存。

## 实际履约判定

以首轮作出的承诺为准。公开回复、意愿工具入参或提醒文本应承诺实际核对某项内容。首轮需要自行预约，随后匹配模型创建的一次性提醒与实际 Schedule 投递。若提前醒来，允许在原承诺下再次预约。醒来后必须读取正式版，文件路径、散列和正文标记都要匹配。随后必须实际将核对结果写入持久记忆，并覆盖首轮承诺的字段。单独的 completed 不算履约。

分析程序把可能履约的会话导出到 review-packet.json。复核者只拿这份无组别标记的文件，检查首轮承诺、后续读取和持久记录是否吻合，再用 reviewId 到布尔值的 JSON 映射提交判断。整个模型上下文仍可能通过回答措辞间接泄漏组别。汇总按配对会话统计，不以预约后的人群代替整体分母。稳定结果要求完整 48 对、整体差值的分层配对 bootstrap 95% 区间下界高于零，以及两张人格卡和至少两种情境同向。

## 复跑

使用已启动的 E30 网络、Docker、Python 3.11+ 和 PyYAML。Soul 需已构建。将 E32_MODEL_CREDENTIAL_CONTAINER 设为已配置实验模型的 DSH 容器。需要通过环境变量 E32_ALICE_PASSWORD 和 E32_BOB_PASSWORD 提供 E30 实验运行凭据，正式会话实际使用由脚本创建的临时账号。容器名可通过 E32_ALICE、E32_BOB 和 E32_CLOUD 覆盖。需要能够在 Cloud 测试容器内执行 Nextcloud OCC 命令。

```bash
python3 run.py seed
python3 run.py smoke --label scoped --port 14240
python3 run.py pilot --label scoped --port 14260
python3 analyze.py .runtime/pilot-scoped
python3 run.py formal --port 14300
python3 analyze.py .runtime/formal
python3 analyze.py .runtime/formal --review review.json
```

run.py 将每个阶段的设计散列、临时目录和配对轨迹写入 .runtime。执行 --label 可保留重试，--seeds 可指定同一批冻结材料。校准审阅后再启动正式阶段。最终摘要将分别列出首轮预约、实际唤醒、正式版读取、醒后读取、可审阅的核对记录和复核通过的履约，供定位行为链在哪一环中止。


## 启用挂心回顾的批次

使用新版 Soul 对照初始是否已有挂心时，在两个阶段命令中加入 `--review-concerns`，另用不同的 `--label` 保存结果。也可以运行 `python3 rerun.py review --review-concerns`，让冒烟测试通过后启动 48 对正式批次。两组都允许在实验中自行新建或回顾挂心，因此「对照」表示首轮没有挂心。正式报告会分别统计新建、按原 ID 更新、搁置和恢复。

每个会话把重新构建的 Soul 注入独立 DSH 配置，复用 E30 的网络和基础容器。此批次沿用冻结的经历、人格和首轮挂心，以及 15 分钟发布、最长 24 小时观察的设计。旧版关闭回顾的批次可用于描述性比较，两次运行的差值需要独立对照才能归因于回顾功能。
